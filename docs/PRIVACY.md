# 何を読み、何を書き、何が外に出るのか

このツールは **あなたと AI アシスタントの会話ログを全部読みます。** それを踏まえて判断できるように、曖昧さを残さず書きます。

「安心してください」で終わる説明は、この文書では役に立ちません。**読む対象・メモリに置くもの・ディスクに書くもの・送信物に入るもの**を、それぞれ具体的に列挙します。

---

## 1. 要点だけ

| | |
|---|---|
| 解析 | **すべてあなたのマシンの中**で完結する |
| ネットワーク | **一切使いません。** このツールは通信をしません |
| 送信 | あなたが JSON を自分で誰かに渡すまで、何も外に出ません |
| 会話本文・コード | **送信物には入りません**（下の §5 に、確かめ方も書いてあります） |

依存パッケージは実行時ゼロです。`node_modules` は開発時のみで、配布物 (`dist/`) は Node の標準ライブラリしか使いません。

---

## 2. 読むもの

### 2.1 常に読むもの

| 対象 | 何のために |
|---|---|
| `~/.claude/projects/**/*.jsonl` | **会話ログ本体。** メイン・サブエージェント・`archived/` の全部 |
| `<cwd>/.claude/settings.local.json` | 権限設定（allow / deny / ask） |
| `<cwd>/.claude/settings.json` | 同上 |
| `~/.claude/settings.json` | 同上 |
| エンタープライズ設定（OS 既定の場所） | 同上 |
| `<cwd>/.mcp.json` | 接続している MCP サーバーの数 |
| `~/.claude.json` | 同上 |
| `<cwd>/.claude/skills/` `~/.claude/skills/` | スキルの**ファイル名だけ**。中身は開きません |

参考までに、開発機での実測は **324 ファイル / 46,215 行 / 約 156 MB** でした。

### 2.2 ファイルシステムに触れるもの

ログから拾った**書き込み先パスの実在確認**を行います（`existsSync`）。

- **1 バイトも読みません。** 存在するかどうかだけ
- 作業ディレクトリの外にも触れます。実測で、ログに出てくるパスの **355 件中 180 件が作業ツリーの外**でした
- 用途: 成果物が今も残っているか（消えたファイルを「定着した成果」と数えないため）

### 2.3 オプトインのもの（既定では読みません）

| 対象 | 有効になる条件 |
|---|---|
| Git のコミット日 | `--repo <path>` を渡したときだけ |
| 外部 CSV | `--external-log <path>` を渡したときだけ |

実行する Git コマンドは**次の 2 つだけ**です。

```
git -C <repo> log --format=%cd --date=short
```

`--repo` を渡したときだけ。コミット日以外は取りません。メッセージも、差分も、著者も読みません。

```
git -C <ストアのパス> ls-files --error-unmatch <ストアのパス>
```

`--store` を渡したときだけ。**ストアが git の管理下に入っていないか**を確かめます。入っていたら実行を拒否します — ストアにはセッション ID・プロジェクト名・コマンド名の鍵付きハッシュが入るので、コミットすると公開してしまうからです。

## 3. メモリに置くもの

会話ログは **1 行ずつ読んで集計し、捨てます。** 本文をメモリに溜めません。

ただし解析中は、以下がプロセス内に存在します:

- 失敗の署名タプル `(ツール名, エラークラス, 対象)`。`対象` はファイル拡張子か、コマンドの第 1 トークン（**私的スクリプト名のことがあります**）
- 編集されたファイルパス（正規化済み）
- 発火したスキル名・フック名・MCP サーバー名

**これらはプロセスの外に出ません。** 出るのは、そこから計算した比率と、鍵付きハッシュ（§4.2）だけです。ソースを見るテストで、署名鍵が payload 生成コードから到達できないことを固定してあります。

---

## 4. ディスクに書くもの

**`--store` を渡さない限り、何も書きません。**

`--store` を付けると `~/.agent-eval/`（`--state-dir` で変更可）に:

| パス | 中身 |
|---|---|
| `~/.agent-eval/snapshots/NNNNNN-<hash>.json` | スナップショット本体 |
| `~/.agent-eval/snapshots/NNNNNN-<hash>.sig.json` | 署名（サイドカー） |
| `~/.agent-eval/snapshots/HEAD.json` | 連鎖の先頭 |
| `~/.agent-eval/.gitignore` | 誤コミット防止 |
| `~/.agent-eval-key` | **このマシン専用の鍵** |

### 4.1 スナップショットに入るもの

`scan`（スコア・行数・日付など、§5 と同じ性質のもの）に加えて:

- **エラークラスの分類名と件数** — `cmd_not_found` 56 件、`no_such_file` 27 件、`other` 84 件、など
- **セッション ID の鍵付きハッシュ** — `h1:01465b0f...`。元の ID そのものは入りません

### 4.2 サイドカーに入るもの（署名 MAC）

失敗署名タプル `(ツール名, エラークラス, 対象)` の **鍵付きハッシュ**が入ります。

**この MAC が何にコミットしているかは、はっきり書いておきます:**

- 鍵はあなたのマシンにしかないので、**鍵を持たない者には読めません**
- ただし**鍵を持つ者は、推測を照合できます。** 「`Bash` で `timeout` が `pytest` に対して起きたか」を当てられれば、その MAC と一致するか確かめられます
- 対象トークンは**私的スクリプト名であることがあります**

つまり MAC は「読めない」のであって「推測に対して無力ではない」わけではありません。

### 4.3 鍵とストアの消し方

```bash
rm -rf ~/.agent-eval        # スナップショットと連鎖
rm -f  ~/.agent-eval-key    # 鍵
```

**鍵を消すと過去のスナップショットの署名は照合できなくなります**（本体のスコアは読めます）。ストアを消すと**履歴は復元できません** — 生ログは Claude Code の保持ポリシーで刈られるため、後から作り直せません。

## 5. 送信物（payload）に入るもの

`agent-eval scan` が標準出力に出す JSON です。**あなたが自分で誰かに渡すまで、どこにも行きません。**

開発機で **16,610 バイト**でした。全項目:

| ブロック | 中身 |
|---|---|
| `schemaVersion` / `runTimestamp` / `submissionId` | スキーマ版・測定時刻・ランダム UUID |
| `scanManifest` | ファイル数・行数・**バイト数**・パースできなかった行数・ツールのバージョン分布・**窓の開始日と終了日**・日付境界のオフセット・各種の分子と分母 |
| `metrics` | 11 指標の分子と分母（率ではなく生カウント） |
| `axes` | 軸ごとのスコア・行の三値内訳・落とした項の**名前**・内訳の数値 |
| `composite` | 総合点と重み |
| `environment` | OS 名・シェル名・ツール名・プロジェクト数・**プロジェクトごとのハッシュ ID / ファイル数 / 行数 / バイト数**・スキル定義数・フック定義数 |

### 5.1 入らないもの

会話本文、コード、ファイルパス、コマンドライン、プロンプト、エラーメッセージ本文、ユーザー名、ホームディレクトリ、プロジェクトのディレクトリ名。

**確かめられます:**

```bash
agent-eval scan > payload.json
grep -c "$USER" payload.json          # 0
grep -c "$HOME" payload.json          # 0
```

### 5.2 それでも注意すべきこと

**「スコアだけ」ではありません。** 気づきにくいものを挙げます。

**プロジェクト ID は無塩の SHA-256 です。** ディレクトリ名（`C--Users-<ユーザー名>-<リポジトリ名>` の形）をそのままハッシュしています。無塩なのは意図的で、**同じプロジェクトが 2 台のマシンで同じ値にならないと比較できない**ためです。代償として、**ユーザー名 × リポジトリ名の組み合わせは列挙可能**なので、受け取った側が推測を当てれば照合できます。「パスに戻せない」ではなく「**推測を確認できる**」です。

**作業した日付が入ります。** `window.windowStart` / `windowEnd` と稼働日数。いつ働いていたかが分かります。

**規模の指紋になります。** プロジェクトごとのバイト数・行数・ファイル数。

**拒否の種別が入ります。** `automode-blocked` / `permission-rule` / `user-rejected` などの件数。

**ツールのバージョン分布が入ります。**

---

## 6. ネットワーク

**このツールは通信をしません。** 実行時依存はゼロで、`dist/` は Node の標準ライブラリだけを使います。

確かめる方法:

```bash
grep -rn "fetch\|https\|http\|net\|tls" dist/ | grep -v "^Binary"
```

外部に何かを送るのは、**あなたが payload を自分で渡したとき**だけです。

---

## 7. まだ書けていないこと

正直に残しておきます。

- **英語版がありません。** 一般配布するなら要ります
- **監査を受けていません。** ここに書いたことはコードから読み取った事実ですが、第三者に確認されたものではありません。`src/collect/` と `src/payload/` を読めば全部たどれます
- **`existsSync` が作業ツリーの外に触れる**点は、実測（355 件中 180 件）を添えて上に書きましたが、これを止めるオプションはまだありません
