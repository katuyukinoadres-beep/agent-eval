# agent-eval

AI エージェント環境の質を、ローカルのログと設定から採点する CLI。

解析はマシン内で完結する。外へ出るのはスコアと分類ラベルだけで、それも opt-in。会話本文とコードは一切送らない。

- **役割分担**: 測定軸の設計は NiKo（`katsu-agents`）、実装は Leon（本リポジトリ）
- **やりとり**: Agent Bridge AB-63 〜（Notion）
- **状態**: Phase 0 着手前。仕様書待ち（下記）

---

## この製品が何を解こうとしているか

既存の Claude Code リーダーボード（CCgather / Viberank / TokenArena / moai-rank）は全てトークン量と支出額を競わせている。だが 2 環境で実測したところ、**総トークンの 94.7〜97.0% はキャッシュ読み出し**で、純粋な生成量は 0.4% 前後しかなかった。量を競う設計は桁で間違っている。

一方、静的な設定採点ツール（skill-doctor / 50-point scorecard / CLAUDE.md grader）は全てワンショット採点で、時系列も母集団比較も持たない。

**「質で採点 × 時系列 × エージェント側と人間側の両面」を同時に満たすものが無い**。そこを狙う。

## 第1弾のスコープ

| # | 内容 |
|---|---|
| ① | **採点エンジン CLI** — ローカル完結。採点 6 軸 + 非採点 2 軸。人間可読サマリと JSON の両方を出す |
| ② | **提出ペイロードの生成とバリデーション** — 吐く側と、**受け取って拒否する側**の両方 |
| ③ | **セッション終了スナップショット** — 後付け不可。最初のリリースに必ず入れる |

**第1弾に含めない**: 母集団比較 / percentile / 人間側ダッシュボード（データは取るが画面に出さない）。

### なぜ ③ が後付け不可なのか

生ログは Claude Code の保持ポリシーで刈られる。実測:

| 環境 | 稼働日数 | ログが残っている割合 |
|---|---|---|
| Leon | 121 日 | **5.8%**（7 日分） |
| NiKo | 120 日 | 25%（30 日分、連続は直近 15 日） |

**初回スキャンで過去半年の推移を作ることは原理的にできない。** 導入時点から前向きに積む以外に成立しない。

## 設計上の確定事項

そのまま実装制約になる。詳細は [docs/DECISION_LOG.md](docs/DECISION_LOG.md)。

- **時系列が第1弾。母集団比較は第2弾** — 時系列はゲーム化に強く、N=1 で成立する
- **提出単位はマシン全体**。プロジェクト別内訳を全件入れ、閾値は設けない
- **率を送らず、分子と分母を生カウントで送る** — 率は定義を埋め込んでしまう
- **改善アドバイスは原因を断定しない** — 「この症状を出す機序は N 通り。区別するにはこれを見ろ」の形
- **三値（`available` / `not_applicable` / `parse_failed`）は行ごとに判定** — 1 環境に 12 バージョン混在の実測あり

## 実装前に潰してある落とし穴

2 環境の実測で確定済み。踏む前に書いておく。

| # | 制約 | 根拠 |
|---|---|---|
| 1 | **走査は必ず再帰** | `glob('*.jsonl')` は `subagents/` を拾わない。全行の 26.7%（NiKo）/ 31.2%（Leon）がサブツリーにある |
| 2 | `isSidechain` をサブエージェント判定に使わない | メイン jsonl では常に false。**パスで判定する** |
| 3 | `toolUseResult.interrupted` を使わない | 2 環境で計 9,995 件のキー出現に対し true が **0 件** |
| 4 | `preventedContinuation` を使わない | 同じく全件 false。**ただし `hookErrors` 非空なら取れる**（下記） |
| 5 | `history.jsonl` を定常データ源にしない | 2 環境とも 2026-04-17 で書き込みが止まっている |
| 6 | `pr-link` を汎用軸に使わない | ドメイン依存（Leon 284 件 / NiKo 0 件） |
| 7 | セッション継続時間を `max - min` で出さない | resume で日を跨ぐため 39 日のセッションが出る。アイドル上限付きの active_minutes 方式に |
| 8 | 率を計算する前に分母の定義を書く | 書けないならその指標はまだ実装しない |
| 9 | **ブール値が 0 / 全 false を返したら、同じ事象が別フィールドを探す** | フィールド名は意味を約束しない。実例 3 件 |

制約 9 の実例が制約 4 でもある。`preventedContinuation` は 278 件すべて false だが、`hookErrors` 非空は 9 件あり、中身は差し戻し文そのものだった。**ブール値が死んでいて実データは隣にある。**

## 定義依存の事故（バリデーションの設計根拠）

設計期間 2 日で 4 件起きた。いずれも「データは正しく取れているのに、比較だけが壊れる」形。

| # | 何の定義 | 振れ幅 | 見つけた側 |
|---|---|---|---|
| 1 | 走査範囲（`subagents/` を含むか） | 1.46 倍 | NiKo |
| 2 | is_error の分母 | 1.96 倍 | NiKo |
| 3 | human 発話の定義 | 2.63 倍 | Leon |
| 4 | 記録率の分母 | **6.9 倍** | Leon |

**うち 2 件は「定義を明示せよ」というルールを書いた本人が直後に破ったもの。** 送る側の規律では止まらないことが 4 回証明された。

だから **受け取り側で拒否する**。マニフェストの無いペイロードは受け付けない。これがこの実装の中心で、ペイロードの形を決めることではない。
